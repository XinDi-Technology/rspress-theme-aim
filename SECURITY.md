# Security Policy 安全策略

## Supported Versions 支持的版本

We currently support the following versions with security updates:
我们目前为以下版本提供安全更新：

| Version | Supported          |
| ------- | ------------------ |
| 2.x     | :white_check_mark: |
| < 2.0   | :x:                |

## Reporting a Vulnerability 报告安全漏洞

### How to Report 如何报告

If you discover a security vulnerability, please report it to us:
如果你发现安全漏洞，请通过以下方式报告：

1. **Do not** create a public GitHub issue
   **不要**创建公开的 GitHub Issue

2. Send an email to: [security@xindi-technology.com](mailto:security@xindi-technology.com)
   发送邮件至：[security@xindi-technology.com](mailto:security@xindi-technology.com)

3. Include the following information:
   包含以下信息：
   - Type of vulnerability (漏洞类型)
   - Full paths of source file(s) related to the vulnerability (相关源文件完整路径)
   - The location of the affected source code (受影响源代码位置)
   - Any special configuration required to reproduce the issue (重现问题所需的特殊配置)
   - Step-by-step instructions to reproduce the issue (重现问题的详细步骤)
   - Proof-of-concept or exploit code (if possible) (概念验证或利用代码（如可能）)
   - Impact of the issue (问题影响)

### What to Expect 预期响应

- **Acknowledgment**: We will acknowledge receipt of your report within 48 hours
  **确认**：我们将在 48 小时内确认收到你的报告

- **Assessment**: We will assess the vulnerability and determine its severity
  **评估**：我们将评估漏洞并确定其严重程度

- **Fix**: We will work on a fix and prepare a release
  **修复**：我们将修复漏洞并准备发布

- **Disclosure**: We will disclose the vulnerability after the fix is released
  **披露**：修复发布后我们将披露漏洞信息

### Disclosure Policy 披露政策

- We follow responsible disclosure practices
  我们遵循负责任的披露实践

- We request that you do not disclose the vulnerability publicly until we have had a chance to address it
  我们请求你在我们有机会解决之前不要公开披露漏洞

- We will credit you for the discovery (unless you prefer to remain anonymous)
  我们将为你署名（除非你希望保持匿名）

## Security Best Practices 安全最佳实践

### For Users 用户

- Always use the latest supported version
  始终使用最新支持的版本

- Keep your dependencies up to date
  保持依赖项最新

- Review and apply security updates promptly
  及时查看并应用安全更新

- Follow the principle of least privilege when configuring the theme
  配置主题时遵循最小权限原则

### For Contributors 贡献者

- Never commit sensitive information (API keys, passwords, etc.)
  永远不要提交敏感信息（API 密钥、密码等）

- Use environment variables for sensitive configuration
  使用环境变量存储敏感配置

- Review dependencies for known vulnerabilities before adding them
  添加依赖前检查已知漏洞

- Follow secure coding practices
  遵循安全编码实践

## Security Updates 安全更新

- Security updates will be released as patch versions
  安全更新将作为补丁版本发布

- We will announce security updates through:
  我们将通过以下方式宣布安全更新：
  - GitHub Security Advisories (GitHub 安全公告)
  - Release notes (发布说明)
  - GitHub Releases (GitHub 发布)
